# Правила проекта

Приложение удаляет настоящие файлы пользователя. Если правило ниже мешает задаче, меняется задача, а не правило.

## 1. Правила чистки

- Всё, что приложение может удалить, описано в `src/main/rules/catalog.ts`. Других способов удаления нет.
- В правило попадает только то, что гарантированно создаётся заново или скачивается. Данные, которые нельзя вернуть, в каталог не добавляются, даже с галочкой «выключено по умолчанию».
- Группа `safe`: чистка незаметна или почти незаметна, `defaultSelected: true`. Группа `slow`: потом что-то работает медленнее или скачивается заново, `defaultSelected: false`.
- `note` объясняет простыми словами, что будет после чистки. Без технических терминов, если можно обойтись.
- Если файл используется работающей программой, её имя указывается в `blockedBy`. Имя сравнивается точно, `*` допускается только в конце.
- Если правило вычисляет план (как образы Android) и данные непонятны, оно возвращает `unavailable`. Угадывать нельзя: при сомнении не удаляем ничего.
- Сторонние форматы (`config.ini`, `ProductInfo.xml`) разбираются по фактическим файлам с этого компьютера, а не по памяти.

Запрещено:

- ослаблять `PROTECTED_SEGMENTS` и `PROTECTED_NAMES` в `domain/safety.ts`;
- расширять разрешённые корни в `isAllowedRoot` без нового правила и теста на него;
- добавлять рекурсивное удаление (`fs.rm`, `rmdir` с `recursive`) и запускать удаление через команды оболочки;
- добавлять правила, для которых нужны права администратора: приложение работает от обычного пользователя;
- трогать корзину, загрузки и документы пользователя.

## 2. Архитектура и IPC

- Направление зависимостей: `infrastructure` → `application` → `domain`. `rules` зависит только от `domain`. К диску ядро обращается через порт `FileSystem`.
- Композиция собирается только в `src/main/index.ts`.
- Контракт IPC описан в `src/shared/contract.ts`. Пути в него не добавляются ни в запросах, ни в ответах, кроме пути к журналу.
- Окно: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, внешняя навигация запрещена, CSP без внешних источников. Не ослаблять.
- Каждый обработчик IPC проверяет отправителя (`handle` в `main/index.ts`).
- `DISK_CLEANER_SANDBOX` работает только в незапакованном приложении.

## 3. Интерфейс

- Обычный текст понятен человеку без технической подготовки. На «ты», без восклицаний.
- Цвета и отступы берутся из переменных в `app/global.css`, новые цвета сначала добавляются туда.
- Всё состояние живёт в чистом редьюсере `features/cleanup/model/reducer.ts`, побочные эффекты в `useCleanup.ts`.
- Мемоизируется всё, без исключений: значения, производные от состояния и пропсов, в том числе примитивы, через `useMemo`, функции через `useCallback`, компоненты через `memo`.
- В JSX нет инлайн-колбэков в списках и обёрток вида `onClick={() => fn()}`, если функция не принимает аргументов.
- Удаление всегда проходит через окно подтверждения; фокус по умолчанию на «Отмена».
- Заблокированную или пустую строку нельзя отметить: это проверяет и редьюсер, а не только `disabled`.
- После заметной правки посмотреть на окно: `node scripts/screenshot.mjs <файл.png>`.

## 4. Тесты

- `npm run check` проходит перед завершением любой задачи. `npm run test:e2e` проходит при изменении интерфейса или IPC.
- Тесты удаления работают на настоящей файловой системе во временной папке (`createSandbox`), а не на моках. Мок допустим только для сбоев, которые нельзя воспроизвести надёжно, например занятого файла.
- Для нового правила обязательны тесты: что удаляется, что остаётся рядом и что происходит на непонятных данных.
- На настоящих данных пользователя тесты ничего не удаляют. Запускать приложение без песочницы и нажимать чистку можно только по просьбе пользователя.
